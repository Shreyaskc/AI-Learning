Chapter 14: Training compute, hardware and inference serving. What a G P U accelerates.

This is a second, optional pass for diagnosing hardware bottlenecks. A byte is a unit of storage; bandwidth is bytes moved per second, and floating point operation counts floating-point arithmetic operations. A C P U excels at flexible control and diverse workloads; a G P U provides many parallel arithmetic units with high-bandwidth device memory. Model execution uses matrix operations, kernels, memory movement, synchronization and communication. Floating-point formats trade range, precision and storage. FP32 typically uses four bytes, BF16 divided by FP16 two bytes, and nominal INT8 one byte per stored value; scales, metadata and packing alter actual memory. BF16 and FP16 have different exponent and mantissa allocations, so equal byte size does not mean identical numerical behavior.

A kernel can be compute-bound when arithmetic throughput limits it, bandwidth-bound when moving bytes limits it, or overhead and communication-bound. Arithmetic intensity is operations per byte moved. A G P U can wait for data even when its arithmetic units are fast. Count both calculations and bytes moved; their ratio is arithmetic intensity. A simple estimate takes the smaller of compute capacity and memory bandwidth times that ratio. This is the roofline model. Peak advertised floating point operation and s is not sustained application throughput.
