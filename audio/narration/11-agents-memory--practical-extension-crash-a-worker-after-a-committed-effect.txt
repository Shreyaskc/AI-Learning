Chapter 11: Workflows, tools, context, memory and graphs. Practical extension: crash a worker after a committed effect.

Run the Python three durable agent lab command shown in the written section. This creates two temporary SQLite databases: one for workflow state and audit and memory and another simulating a separate provider with effects. It starts an actual child process, commits a provider effect, exits abruptly with code 73 before local acknowledgement, then starts a new process to reconcile. It costs no A.P.I. calls and touches no real incident or external account.

A durable operation has The pair consisting of tenant and operation identifier as its primary key, canonical validated payload, state, attempt count, persisted maximum attempts and result. Submission binds the key to its payload; reusing it for another incident is rejected. Trusted code permits only draft ticket with a numeric incident identifier. The tenant argument is an upstream authenticated identity assumption; the teaching script itself does not implement login or issue credentials.

The provider has its own atomic uniqueness constraint and payload check. Inside a write transaction it either returns the previously committed result for the same key and payload or creates exactly one simulated ticket. A different payload for an existing key fails. SQLite transaction semantics support these local transactions, but do not make two independent databases one distributed transaction.

Trace: submit writes PENDING and audit SUBMITTED. Before dispatch, a local transaction increments attempts and writes RUNNING. The provider commits its effect. The injected crash prevents the local SUCCEEDED update, leaving an ambiguous RUNNING state. On restart, recovery checks the provider's operation status before retrying. It finds the committed result and writes SUCCEEDED with audit RECONCILED sub PROVIDER sub EFFECT. The recorded run has one attempt and one provider effect. Repeating recovery returns the same saved result.

If the dispatch fails before an effect exists, retry still uses the same operation key. The attempt budget is stored in the job row: reopening the workflow with a larger default does not silently increase an existing operation's budget. Exhaustion writes STOPPED. Recovery of an already committed effect is allowed before budget rejection, because reading known status does not create a new effect. The tests exercise both paths.

This does not prove exactly-once effects for an arbitrary external tool. Our simulated provider offers definitive status and atomic idempotency. A real provider may have eventually consistent status, limited key retention or no idempotency support. In that case an ambiguous timeout may require waiting, manual reconciliation or a compensating action. A transactional outbox can atomically preserve an intent with local state, but delivery can still repeat; an idempotent consumer and provider or reconciliation remains necessary. Concurrent workers need an ownership mechanism so they do not both act as the current executor. A time-limited ownership grant is a lease; a fencing token lets a provider reject work from a superseded owner. Implementing that coordination is beyond this serial-recovery lab.
