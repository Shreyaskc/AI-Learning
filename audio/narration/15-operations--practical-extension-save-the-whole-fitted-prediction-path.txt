Chapter 15: MLOps, observability and release discipline. Practical extension: save the whole fitted prediction path.

The model-comparison report now contains each selected model's fitted J son artifact: family and schema version, feature order, training-fitted scaler, and learned coefficients, tree nodes or multilayer perceptron weights. It also records implementation SHA-256 and fingerprints for the frozen train and validation and test rows. Unlike an executable pickle, this format stores data and uses an explicit supported-family loader. It is still an educational schema, not a signed or hardened deployment format.

artifact predict takes raw feature values, applies the saved scaler and runs the saved model without retraining. The tests serialize and reload all four families and compare predictions with the original in-memory fitted pipeline. This catches an important training and serving skew: saving weights while forgetting the scaler would change the score despite an identical model family name. A second check replays the committed report's test metrics from its saved artifacts.

A fingerprint helps detect a changed input or implementation; it does not establish that the data is representative, lawful or correctly labeled. For production, add dependency and runtime versions, artifact signing and integrity checks, access controls, deployment compatibility and rollback drills. Treat a changed feature order or scaler schema as a model compatibility change, not a harmless metadata edit.
