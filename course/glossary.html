Glossary and concept index

Each entry separates a technical definition from intuition, an analogy with explicit limits, and a concrete example. Grouped entries contrast related concepts rather than treating them as synonyms. Definitions and analogies are original course prose; linked primary sources check the terminology, not the analogy. These are established foundations or explicitly scoped operational conventions, not claims that one method is always best.

Use the lesson links for derivations and worked practice. Symbols are defined within each entry. The seven bold technical terms currently in lessons open these same layered definitions; other entries remain available in this reference without adding links to ordinary emphasis.

AI

Technical definition: The field concerned with constructing computational systems that perform tasks involving perception, reasoning, learning, planning or action selection. AI includes symbolic and statistical methods; learning from data is not required.

In plain language: AI is the broad discipline; machine learning is one approach within it.

Analogy and its limit: A toolbox for intelligent tasks, not a single tool. Limit: calling a system AI does not establish human understanding.

Concrete example: A rule-based route planner and a learned image classifier are both AI systems.

Machine learning

Technical definition: Methods that fit a model or decision rule from data or experience to improve a specified objective, with generalization assessed on cases beyond the fitting data.

In plain language: Instead of hand-writing every decision, specify data, a model family and a way to judge it.

Analogy and its limit: Learning a recipe from trial batches. Limit: success on the trials need not transfer to new ingredients.

Concrete example: Fit delivery duration from past parcel measurements, then evaluate on later deliveries.

Deep learning

Technical definition: Machine learning with neural networks that compose multiple parameterized transformations, typically learning intermediate representations jointly with an objective.

In plain language: Several learned layers transform raw inputs into useful internal features and outputs.

Analogy and its limit: An assembly line of learned transformations. Limit: layers do not necessarily correspond to human concepts.

Concrete example: An image network learns local patterns and combines them to classify objects.

First explanation: 01 · Sources: Google ML glossary

Generative model

Technical definition: A model specifying or approximating a distribution over observations, possibly conditioned on inputs, from which new observations can be sampled. Some families use implicit sampling rather than tractable likelihoods.

In plain language: It learns how plausible outputs vary so it can generate candidates.

Analogy and its limit: A simulator of possible data. Limit: plausible samples are not evidence that their claims are true.

Concrete example: A language model samples a continuation conditioned on a prompt.

First explanation: 01 · Sources: Google ML glossary

Parameter

Technical definition: A quantity in a model's parameterization whose value is estimated during fitting. For f(x)=wx+b, x is the input, w the fitted coefficient and b the fitted intercept.

In plain language: Parameters store the fitted behavior; a hyperparameter controls how that behavior is learned or constrained.

Analogy and its limit: Adjustable knobs set by fitting. Limit: one knob rarely corresponds to one interpretable fact in a neural network.

Concrete example: Training a delivery-cost model estimates w=2 cost units per kilogram and b=5 cost units.

First explanation: 01 · Sources: Google ML glossary

Hyperparameter

Technical definition: A configuration variable outside the parameter estimation performed by a specified fitting procedure, such as learning rate or maximum tree depth. Validation or an outer optimization may select it.

In plain language: It configures the learning process or model family rather than being fitted by that process as a model weight.

Analogy and its limit: The rules for adjusting the knobs. Limit: an outer search can optimize these rules too; the distinction depends on the fitting procedure.

Concrete example: Compare tree depths 3 and 6 using validation data, then fit the selected configuration.

First explanation: 01 · Sources: Google ML glossary

Feature

Technical definition: An input variable or derived representation supplied to a model for a particular task. A feature must satisfy the task's information-availability contract; it is distinct from the outcome being predicted.

In plain language: Features describe what the model is allowed to observe at prediction time.

Analogy and its limit: Clues available to a detective before a verdict. Limit: a clue can be noisy, misleading or unavailable when needed.

Concrete example: Package weight measured before dispatch is a feature for estimating delivery duration.

First explanation: 01 · Sources: Google ML glossary

Target

Technical definition: The response variable a supervised learning objective asks the model to predict. A training label is an observed or constructed value of that variable and can contain measurement error.

In plain language: The target is the outcome you want to predict; features are the inputs used to predict it.

Analogy and its limit: The destination on a map. Limit: the recorded destination label may itself be wrong.

Concrete example: Observed delivery duration is the target; parcel weight is an input feature.

First explanation: 01 · Sources: Google ML glossary

Example

Technical definition: One observational unit presented to a learning or evaluation procedure. A supervised example typically pairs an input x with a target y; unlabeled examples need not contain y.

In plain language: It is one case, not one feature or one model parameter.

Analogy and its limit: One case file containing evidence and possibly an outcome. Limit: different case files may be statistically dependent.

Concrete example: One parcel's weight and route, paired with its observed delivery duration, form a labeled example.

Training

Technical definition: The process of estimating model parameters or other learned state from data according to a learning objective and fitting procedure. Iterative optimization is common but is not required by every algorithm.

In plain language: Training changes the learned model using experience; inference applies the current learned model.

Analogy and its limit: Rehearsing before a performance. Limit: the algorithm optimizes a specified objective rather than acquiring human comprehension.

Concrete example: A least-squares fit estimates delivery-cost coefficients from historical parcel records.

First explanation: 01 · Sources: Google ML glossary

Inference

Technical definition: In deployed machine learning, evaluating a fitted model on inputs to produce predictions, scores or samples, ordinarily without updating its fitted parameters. Statistical inference also has a broader meaning: drawing conclusions about unknown quantities from data.

In plain language: Here it means using the model, not fitting it. Generated text may be sampled rather than deterministic.

Analogy and its limit: Playing a prepared musical score. Limit: sampling or online adaptation can make repeated uses differ.

Concrete example: Apply fixed delivery-time coefficients to a new parcel's measurements to obtain a duration estimate.

First explanation: 01 · Sources: Google ML glossary

Self-supervised learning

Technical definition: Learning from supervisory signals constructed from the observed data itself, such as predicting masked content or a next element, rather than requiring a separate human label for each example.

In plain language: The data supplies the prediction task; it still has targets and a loss.

Analogy and its limit: A puzzle with pieces temporarily hidden. Limit: the puzzle objective may not teach the downstream skill you care about.

Concrete example: Mask a word in a sentence and train a model to predict it from the remaining words.

First explanation: 01 · Sources: Google ML glossary

Leakage

Technical definition: A violation of the intended learning or evaluation information boundary in which fitting or prediction uses information unavailable under the claimed deployment protocol, biasing the performance estimate.

In plain language: The model gets a clue it would not really have when making the decision.

Analogy and its limit: Seeing tomorrow's newspaper before today's forecast. Limit: whether information leaks depends on the decision time and permitted information.

Concrete example: Using actual arrival time to predict delivery delay before dispatch leaks the outcome.

Baseline / ablation

Technical definition: A baseline is a reference system or rule used for comparison. An ablation is a controlled change that removes or alters a component to measure its contribution under the evaluation protocol.

In plain language: A baseline asks what improvement you achieved; an ablation asks which component caused it.

Analogy and its limit: Compare a recipe with a simple dish, then omit one ingredient. Limit: interacting ingredients can make isolated effects misleading.

Concrete example: Compare a model with the historical median predictor; then remove route features and repeat the same evaluation.

First explanation: 01 · Sources: Google ML glossary

Tensor / shape / dtype

Technical definition: In array programming, a tensor is a multidimensional array; shape lists axis lengths, and dtype specifies element representation and numerical precision. This usage does not require the transformation laws of mathematical tensors.

In plain language: Values, their arrangement and their number format are separate properties.

Analogy and its limit: An organized set of boxes, its dimensions and the type of contents. Limit: actual layouts may be sparse, strided or distributed.

Concrete example: A float32 tensor of shape (32,10) contains 32 rows of 10 values.

First explanation: 02 · Sources: PyTorch tensors

Dot product

Technical definition: For equal-length real vectors x and y, their dot product is the sum of x_i times y_i over coordinates i. It combines magnitudes and relative direction; it is not normalized similarity.

In plain language: Multiply matching coordinates and add the products.

Analogy and its limit: A weighted tally of matching signals. Limit: a large score can reflect large magnitudes rather than close directions.

Concrete example: For x=(1,2) and y=(3,4), the dot product is 1×3+2×4=11.

First explanation: 02 · Sources: Linear algebra

Norm / cosine

Technical definition: A norm measures vector size and satisfies positivity, homogeneity and the triangle inequality. Euclidean norm is the square root of summed squared coordinates. Cosine similarity is the dot product divided by the product of nonzero vectors' Euclidean norms.

In plain language: Norm measures size; cosine measures directional agreement after removing size.

Analogy and its limit: Arrow length versus arrow alignment. Limit: geometric similarity need not equal semantic relevance, and cosine is undefined for a zero vector.

Concrete example: Vectors (1,0) and (2,0) have different norms but cosine similarity 1.

First explanation: 02 · Sources: Linear algebra

Rank / SVD / PCA

Technical definition: Matrix rank is the dimension of its column space. Singular value decomposition factors a matrix into orthogonal directions and nonnegative singular values. PCA projects centered data onto directions maximizing retained variance, often computed using SVD.

In plain language: Rank counts independent directions; SVD exposes directions and strengths; PCA chooses a variance-preserving subset.

Analogy and its limit: Rotate a cloud of points to view its widest axes. Limit: the widest variation may be irrelevant to prediction.

Concrete example: Centered points lying on one straight line have rank at most 1; one principal component captures their variation.

First explanation: 02 · Sources: PCA documentation

Logit

Technical definition: In binary probability models, logit(p)=ln(p/(1−p)) for probability p between 0 and 1. In neural classifiers, logits more generally denote real-valued scores before sigmoid or softmax normalization.

In plain language: A logit is a raw score, not yet a probability.

Analogy and its limit: A race score before converting scores into betting shares. Limit: normalization alone does not make predictions calibrated.

Concrete example: Binary probability 0.8 has log odds ln(4), approximately 1.386.

First explanation: 02, 05 · Sources: Logistic regression

Softmax

Technical definition: A function mapping scores z_i to probabilities exp(z_i)/sum_j exp(z_j) over a finite set. Subtracting a common constant from all scores leaves the result unchanged and improves numerical stability.

In plain language: It converts relative scores into positive shares summing to one.

Analogy and its limit: Dividing a budget with exponentially score-weighted shares. Limit: those shares are model outputs, not proof of calibrated real-world probabilities.

Concrete example: Scores (0,0) yield (0.5,0.5); adding 10 to both scores changes nothing.

First explanation: 02 · Sources: Numerical computation

Gradient / chain rule

Technical definition: The gradient of a differentiable scalar function is the vector of partial derivatives with respect to its inputs. The chain rule computes derivatives of compositions by combining local derivatives or Jacobians.

In plain language: The gradient gives local sensitivity; the chain rule carries that sensitivity through successive computations.

Analogy and its limit: Slopes on a landscape, connected through a sequence of paths. Limit: local slope gives no general guarantee of reaching the global optimum.

Concrete example: If loss is (w−3)^2, its gradient with respect to w is 2(w−3).

First explanation: 02 · Sources: Numerical computation

Conditional probability

Technical definition: For events A and B with P(B)>0, P(A given B)=P(A and B)/P(B). Conditioning restricts or updates the probability model using B; it does not by itself describe an intervention.

In plain language: Ask how likely A is among cases where B holds.

Analogy and its limit: Filtering a deck before counting a card type. Limit: filtering observations is not the same as causing the filter condition.

Concrete example: If 20 of 50 rainy days had delays, the observed delay frequency conditional on rain is 0.4.

First explanation: 03 · Sources: Probability foundations

Prior / likelihood / posterior

Technical definition: A prior assigns probabilities to hypotheses before the current observations. The likelihood treats the probability or density of observed data as a function of a hypothesis. The posterior is proportional to likelihood times prior, normalized over hypotheses.

In plain language: Start with beliefs, measure how well each explains the evidence, then update.

Analogy and its limit: Reweighting candidate explanations after a new clue. Limit: the update is only as sound as the prior and data model.

Concrete example: A Beta(1,1) prior for a coin's heads probability becomes Beta(4,2) after 3 heads and 1 tail.

First explanation: 03 · Sources: Probability foundations

Expectation / variance

Technical definition: Expectation is the probability-weighted mean of a random variable when defined. Variance is the expected squared difference from that mean, when finite; it measures dispersion rather than estimation uncertainty.

In plain language: Expectation gives an average outcome; variance gives how widely outcomes vary.

Analogy and its limit: A balance point and spread around it. Limit: neither alone describes multimodality or heavy tails.

Concrete example: A fair outcome equally likely to be 0 or 2 has expectation 1 and variance 1.

First explanation: 03 · Sources: Probability foundations

Standard error

Technical definition: The standard deviation of an estimator's sampling distribution, usually estimated from data. For an independent identically distributed sample mean with finite variance, it equals population standard deviation divided by the square root of sample size.

In plain language: It measures how much an estimate would vary across repeated samples, not how much individual outcomes vary.

Analogy and its limit: Variation between batches' averages. Limit: dependence and biased sampling invalidate a naive square-root rule.

Concrete example: With independent outcomes of standard deviation 10 and sample size 100, the mean's standard error is 1.

First explanation: 03 · Sources: Probability foundations

Confidence / credible interval

Technical definition: A 95% confidence-interval procedure covers a fixed parameter in 95% of repeated samples under its assumptions. A 95% credible interval contains 95% of a Bayesian posterior probability conditional on the observed data and model.

In plain language: One describes a procedure's long-run coverage; the other describes posterior uncertainty for this dataset.

Analogy and its limit: A repeatedly reliable net versus a region holding posterior mass. Limit: these are different probability statements, not interchangeable labels.

Concrete example: A reported frequentist interval does not assign a 95% probability to the fixed parameter lying in that realized interval.

First explanation: 03 · Sources: Probability foundations

Entropy / cross-entropy

Technical definition: For discrete distributions, entropy is the expected negative log probability under the same distribution. Cross-entropy averages negative log probabilities assigned by a candidate distribution to outcomes from a reference distribution.

In plain language: Entropy measures inherent distributional uncertainty; cross-entropy also penalizes a mismatched prediction distribution.

Analogy and its limit: Optimal code length versus length under a mismatched codebook. Limit: coding intuition assumes the specified probability model and log base.

Concrete example: For a fair binary variable, entropy is 1 bit; always predicting probability 0.9 for heads gives larger cross-entropy.

First explanation: 03 · Sources: Probability foundations

KL divergence

Technical definition: For discrete distributions P and Q, KL(P∥Q) is the sum of P(x)ln(P(x)/Q(x)) over outcomes with positive P. It is nonnegative, generally asymmetric and infinite if Q assigns zero where P is positive.

In plain language: It measures the extra expected log loss from using Q when outcomes follow P.

Analogy and its limit: A directional cost of using the wrong codebook. Limit: it is not a symmetric geometric distance.

Concrete example: KL(P∥P)=0; reversing P and Q can change the divergence.

First explanation: 03 · Sources: Probability foundations

Confounding

Technical definition: In causal inference, confounding arises when exposure or treatment and outcome share causes that leave observed treatment groups nonexchangeable for estimating a causal effect without adjustment or other identification assumptions.

In plain language: An observed association may mix the treatment's effect with differences between the groups.

Analogy and its limit: Comparing runners wearing different shoes when one group trains more. Limit: adjusting arbitrary variables can introduce rather than remove bias.

Concrete example: Temperature can cause both ice-cream purchases and swimming activity; their association alone does not show purchases cause swimming.

First explanation: 03 · Sources: Probability foundations

Aleatoric / epistemic

Technical definition: Aleatoric uncertainty is variability in outcomes conditional on the available information. Epistemic uncertainty concerns uncertain model parameters, structure or knowledge. The separation depends on the model and what is observed.

In plain language: Some uncertainty remains given current inputs; some comes from not knowing enough about the model or domain.

Analogy and its limit: Weather variability versus an uncertain forecast model. Limit: adding sensors can turn apparently irreducible variability into explained variation.

Concrete example: More training data may reduce coefficient uncertainty while delivery duration still varies for identical recorded features.

First explanation: 03 · Sources: Model uncertainty study

Empirical risk

Technical definition: The average loss of a model over a finite sample: sum_i loss(f(x_i),y_i)/n, where n is example count, x_i inputs and y_i targets. It estimates population risk under sampling assumptions.

In plain language: It is the model's average penalty on the observed dataset.

Analogy and its limit: Average score on a practice set. Limit: a low practice penalty need not mean low future penalty.

Concrete example: Squared errors 1,4 and 4 give empirical risk 3.

First explanation: 04 · Sources: SGD objective and regularization

SGD / batch / epoch

Technical definition: Stochastic gradient descent updates parameters using gradients estimated from sampled training examples. A minibatch is the examples used for one such gradient estimate; an epoch is one pass through the training dataset under a defined sampling convention.

In plain language: A batch controls one update's evidence; an epoch counts dataset passes, not updates.

Analogy and its limit: Learning from small stacks of cards before reshuffling. Limit: streaming or replacement sampling may have no literal full pass.

Concrete example: With 1000 examples and batch size 100, one full pass has 10 updates if no examples are dropped.

First explanation: 04 · Sources: SGD objective and regularization

Regularization

Technical definition: A change to an objective, constraint or fitting procedure that favors selected solution properties to improve generalization or identifiability. Explicit norm penalties and early stopping are examples; not all regularization is an added loss term.

In plain language: It restricts or biases what solutions training can choose.

Analogy and its limit: A guardrail that discourages fragile shortcuts. Limit: the chosen bias can suppress useful signal too.

Concrete example: Adding lambda times the sum of squared coefficients penalizes large weights; lambda controls the penalty strength.

First explanation: 04 · Sources: SGD objective and regularization

Momentum / Adam

Technical definition: Momentum maintains a moving accumulation of gradients to influence updates. Adam uses bias-corrected moving estimates of first and second gradient moments to scale coordinate-wise updates, with stabilizing constants and a learning rate.

In plain language: Momentum smooths update direction; Adam also adapts scaling per coordinate.

Analogy and its limit: A rolling ball versus a ball with adjustable traction. Limit: optimizer dynamics are not literal physical motion and convergence is not universal.

Concrete example: Repeated positive gradients accumulate directional momentum; Adam divides a first-moment estimate by a stabilized square-root second-moment estimate.

First explanation: 04 · Sources: Adam paper

Underfitting / overfitting

Technical definition: Underfitting is inadequate capture of relevant data structure, often visible as poor training and held-out performance. Overfitting is adapting to sample-specific patterns that lower fitting loss without corresponding generalization improvement.

In plain language: Too little relevant fit versus too much reliance on quirks of the sample.

Analogy and its limit: A straight ruler for a curve versus tracing every bump. Limit: model size alone does not determine either condition.

Concrete example: Training error keeps falling while validation error rises after additional fitting: evidence consistent with overfitting.

First explanation: 04 · Sources: SGD objective and regularization

Logistic regression

Technical definition: A generalized linear model for binary outcomes with log odds equal to an affine function of features: p=1/(1+exp(−(w·x+b))), where p is predicted positive probability, w coefficients and b intercept.

In plain language: It fits a linear score and maps it through a sigmoid to a probability.

Analogy and its limit: A weighted evidence scale with an S-shaped output dial. Limit: the probability curve is nonlinear but the log-odds decision boundary is linear in supplied features.

Concrete example: A positive weight on route distance raises predicted delay odds when other features are held fixed.

First explanation: 05 · Sources: Linear models

Margin / kernel

Technical definition: A classification margin measures signed separation from a decision boundary under a specified score or geometric normalization. A positive-semidefinite kernel gives inner products in an implicit feature space, enabling algorithms to use that space without constructing its coordinates.

In plain language: Margin describes separation; a kernel supplies a feature-space similarity operation.

Analogy and its limit: A safety buffer around a boundary and a different coordinate lens. Limit: an arbitrary similarity function need not be a valid kernel.

Concrete example: An RBF kernel compares points by exp(−gamma times squared distance), with gamma controlling locality.

First explanation: 05 · Sources: Linear models

Bagging / boosting

Technical definition: Bagging fits learners on resampled datasets and aggregates their predictions, commonly reducing variance. Boosting builds an additive model sequentially, with later learners selected to improve a loss or emphasize remaining errors.

In plain language: Bagging combines partly independent fits; boosting corrects the current ensemble step by step.

Analogy and its limit: A panel of independent judges versus successive editors. Limit: learners are not necessarily independent and neither method guarantees improvement.

Concrete example: A random forest aggregates randomized trees; gradient boosting adds trees fitted to loss-gradient information.

First explanation: 05 · Sources: Ensemble methods

Precision / recall

Technical definition: At a fixed decision rule, precision is true positives divided by predicted positives; recall is true positives divided by actual positives. Undefined zero-denominator cases require an explicit convention.

In plain language: Precision asks how many alerts were correct; recall asks how many positives were caught.

Analogy and its limit: A fishing net's catch purity versus coverage of desired fish. Limit: the analogy omits the costs of different errors.

Concrete example: Of 20 alerts, 15 are true positives; among 30 actual positives, precision is 0.75 and recall 0.5.

First explanation: 06 · Sources: Prediction metrics

Calibration

Technical definition: A binary probability predictor is calibrated if, conditional on predicting p, the event frequency is p, in the population under consideration. Finite-data reliability diagrams estimate this property using bins or smoothing.

In plain language: Among predictions near 0.7, about 70% should be positive; calibration is different from ranking or accuracy.

Analogy and its limit: An honest confidence dial. Limit: an honest average dial can still hide subgroup failures and distribution shifts.

Concrete example: Of 1000 similar cases scored near 0.8, roughly 800 positives is consistent with calibration in that score range.

First explanation: 06 · Sources: Calibration documentation

Brier score

Technical definition: For a binary event, the mean of (p_i−y_i)^2 across examples, where p_i is predicted probability and y_i is 0 or 1. Lower is better; it reflects both calibration and discrimination.

In plain language: It penalizes squared probability mistakes, not only incorrect hard labels.

Analogy and its limit: A penalty for how far confidence misses the outcome. Limit: it is not a pure calibration metric.

Concrete example: Predicting 0.8 for an event that occurs incurs (0.8−1)^2=0.04.

First explanation: 06 · Sources: Prediction metrics

Contamination

Technical definition: Exposure of evaluation examples, answers or closely related information to training or development in a way that compromises the claimed independence or novelty of the evaluation. It is a specific threat to evaluation validity.

In plain language: A benchmark may measure prior exposure rather than the capability it claims to test.

Analogy and its limit: A student seeing the exam before the test. Limit: related material is not automatically disqualifying; the evaluation contract determines the boundary.

Concrete example: Tuning prompts repeatedly against a test answer key turns that test into development data.

First explanation: 06 · Sources: Prediction metrics

Drift / abstention

Technical definition: Drift is a change in a relevant data, target or relationship distribution over time or environments. Abstention is a decision policy that declines to issue an automated prediction or action on selected cases.

In plain language: Drift changes conditions; abstention controls when the system refuses automation.

Analogy and its limit: Road conditions change; a driver may pull over. Limit: refusing difficult cases changes the population on which metrics are measured.

Concrete example: If new package types arrive, monitor slice errors and route unsupported types to human review.

First explanation: 06 · Sources: Prediction metrics

Activation / residual

Technical definition: An activation is a transformation applied to neural-unit or layer outputs, often nonlinear. A residual connection adds a shortcut input to a learned transformation, such as output=x+F(x), requiring compatible dimensions or a projection.

In plain language: Activations enable nonlinear behavior; residual paths let a block learn corrections to a carried-forward signal.

Analogy and its limit: A switch versus a bypass lane with an added correction. Limit: residuals are not guarantees against vanishing gradients or bad optimization.

Concrete example: ReLU maps negative values to zero; a residual block adds its transformed vector to the input vector.

First explanation: 07 · Sources: Google ML glossary

Backprop / autograd

Technical definition: Backpropagation efficiently accumulates derivatives through a computation graph using the reverse-mode chain rule. Automatic differentiation is software evaluation of derivatives from elementary operations; it includes reverse and forward modes and is not finite differencing.

In plain language: Backprop is a derivative algorithm; autograd is machinery that implements differentiation of recorded computations.

Analogy and its limit: An accounting trail that sends responsibility backward. Limit: derivatives measure local sensitivity, not causal responsibility.

Concrete example: For loss=(2w)^2, reverse-mode differentiation accumulates dloss/dw=8w.

First explanation: 07 · Sources: Automatic differentiation

Convolution / recurrence

Technical definition: A convolutional layer applies shared local filters across positions, usually using cross-correlation in implementations. Recurrence repeatedly applies a state-update function across a sequence, making the current state depend on prior state and input.

In plain language: Convolution shares a local pattern detector across locations; recurrence carries state through steps.

Analogy and its limit: A sliding stencil versus a running notebook. Limit: neither architecture alone guarantees long-range understanding or invariance.

Concrete example: A 1D filter detects local sound patterns; a recurrent network updates hidden state for each audio frame.

First explanation: 07 · Sources: Google ML glossary

Tokenizer / BPE

Technical definition: A tokenizer maps input text to a sequence of tokens and identifiers under a defined normalization and segmentation scheme. Byte-pair encoding learns iterative merges of frequent adjacent symbols; byte-level variants begin from bytes.

In plain language: Tokenization determines the model's discrete text pieces; BPE is one way to learn those pieces.

Analogy and its limit: Cutting text into reusable tiles. Limit: tiles need not be words or align across languages, and some normalization is lossy.

Concrete example: A rare word can split into several subword tokens rather than one unknown-word identifier.

First explanation: 08 · Sources: Google ML glossary

Embedding

Technical definition: A mapping of discrete or structured objects into a vector space, often learned so geometric relationships help a training objective. In an embedding table, an object's identifier selects a fitted vector; contextual embeddings also depend on surrounding input.

In plain language: An embedding is a particular vector representation; representation is the broader term and need not be learned or dense.

Analogy and its limit: Placing items on a task-shaped map. Limit: proximity reflects the objective and data, not universal meaning or truth.

Concrete example: A retrieval encoder maps a query and passages to vectors; the matching score helps select candidate passages.

First explanation: 08 · Sources: Sentence-BERT paper

Query / key / value

Technical definition: In scaled dot-product attention, queries and keys produce compatibility scores; softmax-normalized scores weight value vectors. For matrices Q,K,V, attention is softmax(QK^T/sqrt(d_k))V, where d_k is query/key width and T denotes transpose.

In plain language: Queries ask what to match, keys determine matching, and values supply the mixed content. These are vector roles, not database records.

Analogy and its limit: A request, index cards and the content selected through them. Limit: attention usually blends many values rather than retrieving a single record.

Concrete example: One token's query scores earlier tokens' keys; their values are combined using the resulting weights.

First explanation: 08 · Sources: Transformer paper

Causal mask

Technical definition: A restriction on attention or another sequence dependency that blocks a prediction from using positions later than permitted by the autoregressive factorization. Blocked attention scores are typically set to negative infinity before softmax.

In plain language: The next-token predictor cannot peek at future tokens while training.

Analogy and its limit: A screen covering the unread part of a sentence. Limit: masking attention cannot repair future information already leaked through features or preprocessing.

Concrete example: At sequence position 3, a causal self-attention layer may attend to positions 1 through 3, not 4.

First explanation: 08 · Sources: Transformer paper

Autoregressive / teacher forcing

Technical definition: An autoregressive model factors a joint sequence probability into successive conditional probabilities given preceding elements. Teacher forcing trains conditional predictions using observed preceding target elements rather than the model's sampled prefix.

In plain language: Autoregression defines the dependency structure; teacher forcing specifies the training inputs.

Analogy and its limit: Learning a route from correct prior turns, then driving using your own turns. Limit: prediction errors can change later inputs at generation time.

Concrete example: Training predicts the fourth token from the three true earlier tokens; generation uses the three tokens actually produced.

First explanation: 08 · Sources: Transformer paper

Temperature / top-p

Technical definition: Temperature divides sampling logits by a positive scalar before normalization; higher values flatten the resulting distribution. Top-p sampling retains the smallest probability-ranked prefix reaching a chosen cumulative mass, then renormalizes for sampling.

In plain language: Temperature changes relative randomness; top-p removes the lower-probability tail.

Analogy and its limit: Adjusting how uneven a raffle is, then removing the longest-shot tickets. Limit: neither setting establishes correctness or calibrated uncertainty.

Concrete example: With top-p=0.9, keep enough highest-probability tokens to cover at least 90% of the mass before sampling.

First explanation: 08 · Sources: Nucleus sampling

Perplexity

Technical definition: The exponential of mean negative log likelihood using natural logs, typically over evaluated tokens. It is a geometric measure of predictive uncertainty; comparisons require compatible tokenization, data and probability accounting.

In plain language: Lower perplexity means the model assigned more probability to the observed sequence under that evaluation setup.

Analogy and its limit: An effective average branching factor. Limit: it is not a literal fixed number of choices and does not directly measure usefulness or truth.

Concrete example: Mean token negative log likelihood ln(4) gives perplexity 4.

First explanation: 09 · Sources: Google ML glossary

SFT / PEFT / LoRA

Technical definition: Supervised fine-tuning updates a pretrained model using labeled input-output examples. Parameter-efficient fine-tuning adapts a restricted set or parameterization of trainable quantities. LoRA fits a low-rank additive weight update while freezing original weights; these categories overlap.

In plain language: SFT is an objective/data setup; PEFT is an adaptation strategy; LoRA is one PEFT mechanism.

Analogy and its limit: Teaching with demonstrations while replacing only a small adjustment module. Limit: fewer trainable parameters do not guarantee better results or negligible runtime cost.

Concrete example: Apply SFT to desired responses while representing a weight update as BA, where B and A are smaller trainable matrices.

First explanation: 09 · Sources: LoRA paper

Policy / reward / return

Technical definition: In reinforcement learning, a policy maps states or histories to action distributions. A reward is a scalar feedback signal for a transition or step. Return aggregates future rewards, often with discounting, under a specified horizon.

In plain language: The policy decides; rewards score steps; return scores an extended outcome.

Analogy and its limit: A strategy, points per move and the game's accumulated score. Limit: the score may poorly represent the intended benefit.

Concrete example: A delivery-routing policy chooses a road; time cost gives negative reward, and discounted accumulated reward defines return.

First explanation: 09 · Sources: RLHF training paper

RLHF / DPO

Technical definition: Reinforcement learning from human feedback uses human-derived feedback to construct rewards or preferences and optimize a policy. DPO fits preference-pair likelihood ratios relative to a reference policy under a specific preference model, without the separate explicit reward-model-plus-RL loop of common RLHF pipelines.

In plain language: RLHF is a broader feedback-based approach; DPO is a particular direct preference objective.

Analogy and its limit: Learning from judges via a score model versus directly comparing preferred performances. Limit: preferences can be inconsistent and neither method guarantees alignment with all human values.

Concrete example: Use preferred and rejected responses for the same prompt to adjust a policy's relative probabilities under DPO.

First explanation: 09 · Sources: RLHF, DPO

Reward hacking

Technical definition: Behavior that increases an optimization reward or proxy while failing to improve, or harming, the intended objective. It can arise from misspecified metrics and need not involve intent or awareness.

In plain language: The system wins the scoring rule instead of delivering the desired outcome.

Analogy and its limit: Teaching to a flawed scoreboard. Limit: the failure is objective mismatch, not evidence of deliberate deception.

Concrete example: A response policy learns to produce long praise because raters reward it, even when factual usefulness falls.

BM25 / ANN

Technical definition: BM25 is a lexical retrieval scoring family combining query-term matches, inverse document frequency and saturated term frequency with document-length normalization. Approximate nearest-neighbor search trades exact top-neighbor guarantees for efficiency under a vector similarity or distance.

In plain language: BM25 scores word matches; ANN accelerates similarity search and is not itself an embedding model.

Analogy and its limit: An optimized word index versus a shortcut through a geometric map. Limit: lexical and vector retrieval can each miss relevant documents.

Concrete example: Retrieve manuals with BM25 for exact part numbers and with ANN for embedding similarity.

Bi-encoder / cross-encoder

Technical definition: A bi-encoder encodes query and candidate separately and compares their representations, enabling candidate precomputation. A cross-encoder jointly processes a query-candidate pair to produce a relevance score, usually requiring per-pair computation.

In plain language: Independent encoding scales first-stage retrieval; joint encoding can model detailed pair interactions.

Analogy and its limit: Compare prepared summaries versus read both documents together. Limit: the joint model is not automatically more accurate on every dataset.

Concrete example: Retrieve 100 candidates by vector score, then jointly score each query-passage pair with a cross-encoder.

Reranker / hybrid retrieval

Technical definition: A reranker rescores or reorders a candidate set; it cannot recover absent candidates unless it performs additional retrieval. Hybrid retrieval combines different retrieval signals or result sets, such as lexical and dense-vector search, using a defined fusion strategy.

In plain language: Hybrid search broadens candidate evidence; reranking refines an existing candidate pool.

Analogy and its limit: Gather candidates from two scouts, then conduct final interviews. Limit: the finalist selector cannot choose someone never shortlisted.

Concrete example: Fuse BM25 and dense ranks, then rerank the top 50 passages.

RAG / grounding / provenance

Technical definition: Retrieval-augmented generation conditions generation on information retrieved from an external collection. Grounding concerns whether output is supported by specified evidence or environment. Provenance records the origin and transformations of information; a citation alone does not prove support.

In plain language: RAG is a method; grounding is an evidence relationship; provenance is a trace of origin.

Analogy and its limit: An open-book answer, its supporting passages and their chain of custody. Limit: opening the book does not ensure the answer follows it.

Concrete example: Retrieve a versioned manual, generate an answer and retain passage IDs plus versions so a reviewer can check each claim.

Tool / workflow / agent

Technical definition: A tool is an externally callable operation with an interface and effects. A workflow defines control flow among operations. In this course, an agent is a system in which a model selects actions iteratively using observations; terminology varies across the field.

In plain language: A tool performs an operation, a workflow coordinates steps, and an agent chooses some steps dynamically.

Analogy and its limit: An instrument, a recipe and a cook choosing the next move. Limit: agentic choice does not grant authority or guarantee competence.

Concrete example: A model selects a read-only search tool, observes results and decides whether another search is needed within a step budget.

Idempotency

Technical definition: An operation is idempotent if repeating it has the same intended state effect as performing it once. For retryable APIs, a logical-operation key is commonly used to deduplicate effects; response bytes need not be identical.

In plain language: Retries should not create extra real-world effects for the same logical request.

Analogy and its limit: Pressing the same elevator-floor button twice. Limit: implementations must define key scope, retention and concurrent-request handling.

Concrete example: Retrying a job-creation request with the same idempotency key returns the original job instead of creating a second one.

Context / memory

Technical definition: Context is the information made available to a particular model invocation, including input tokens or supported modalities. Application memory is retained information across invocations that may be selectively added to future context; it is distinct from fixed model weights.

In plain language: Context is what is on the desk now; memory is what can be fetched for later desks.

Analogy and its limit: A working desk and a filing cabinet. Limit: stored information is not automatically present, accurate or authorized for every request.

Concrete example: Store a user-approved preference, then retrieve it into a later prompt only for an authorized relevant task.

Knowledge graph / entity resolution

Technical definition: A knowledge graph represents entities and typed relationships, often with attributes and provenance. Entity resolution determines which records or mentions refer to the same real-world entity using rules or statistical evidence.

In plain language: The graph stores relationships; entity resolution decides which references identify the same thing.

Analogy and its limit: A labeled relationship map and the process of merging duplicate name cards. Limit: merging errors can spread false relationships.

Concrete example: Resolve two supplier records to one company ID before linking it to contracts and locations.

OCR / WER / diarization

Technical definition: Optical character recognition extracts text from images. Word error rate is (substitutions+deletions+insertions)/reference word count after specified text normalization. Speaker diarization assigns speech intervals to speaker identities or anonymous labels.

In plain language: OCR reads pixels; WER scores transcripts; diarization separates who spoke when.

Analogy and its limit: Reading a photographed page, proofreading a transcript and labeling voices. Limit: speaker labels do not necessarily identify named people.

Concrete example: A 10-word reference with 1 substitution and 1 deletion has WER 0.2; extra insertions can make WER exceed 1.

VAE / GAN / diffusion

Technical definition: A variational autoencoder learns a latent-variable generative model using a variational bound on log likelihood. A GAN trains a generator against a discriminator or critic. Diffusion models learn reverse generative transitions or related denoising/score objectives from a specified corruption process.

In plain language: These are different training and generation mechanisms, not interchangeable names for image generation.

Analogy and its limit: A compressed latent recipe, an adversarial art contest and progressive restoration from noise. Limit: these metaphors omit the probability objectives.

Concrete example: A VAE samples a latent code and decodes it; a diffusion sampler iteratively transforms noise toward a sample.

Event / availability time

Technical definition: Event time records when an event occurred in the modeled world. Availability time records when the information became accessible to a particular system or decision process. Historical evaluation must respect both where required.

In plain language: When something happened is different from when your system could know it.

Analogy and its limit: The date on a letter versus its delivery date. Limit: multiple systems may have different availability times for the same event.

Concrete example: A scan occurs at 10:00 but arrives in the feature service at 10:07; a 10:03 decision cannot use it.

Feature store / backfill / skew

Technical definition: A feature store manages reusable feature definitions, materializations and access with relevant consistency contracts. A backfill computes historical values. Train-serve skew is a mismatch between fitting/evaluation and serving feature or processing behavior; identical column names do not prevent it.

In plain language: Manage shared inputs, reconstruct their past values and check that training and serving agree.

Analogy and its limit: A shared ingredient catalog, historical pantry reconstruction and checking both kitchens use the same recipe. Limit: a catalog alone cannot enforce time correctness.

Concrete example: A backfill must use the exchange-rate version available at each past decision time, not today's corrected value.

FLOP / bandwidth

Technical definition: A FLOP is one floating-point operation under a specified counting convention. FLOP/s measures operation throughput. Bandwidth measures transferred data per time; memory and network bandwidth differ. Runtime depends on utilization, movement, latency and compute, not only peak specifications.

In plain language: Count arithmetic separately from how fast numbers move.

Analogy and its limit: Worker speed versus conveyor capacity. Limit: neither peak number alone predicts end-to-end performance.

Concrete example: A kernel moving 8 GB at an effective 1 TB/s needs at least about 8 ms for transfer, excluding other costs.

Data / tensor / pipeline parallelism

Technical definition: Data parallelism distributes examples across model replicas and combines updates. Tensor parallelism partitions computations or tensors within layers. Pipeline parallelism assigns layer stages to devices and schedules microbatches through them.

In plain language: Split the data, split a layer, or split the layer sequence: these have different communication costs.

Analogy and its limit: Multiple kitchens, a shared large chopping task, or an assembly line. Limit: real systems combine these strategies and incur synchronization or idle bubbles.

Concrete example: Use data-parallel replicas, each internally tensor-parallel, when a full layer cannot efficiently run on one device.

Collective / sharding

Technical definition: A collective is a communication operation involving a defined process group, such as all-reduce or all-gather. Sharding partitions data or model state across workers; communication reconstructs or aggregates information when needed.

In plain language: Collectives describe coordination; sharding describes where pieces live.

Analogy and its limit: A group call versus distributing pages of a ledger. Limit: a shared logical view does not imply every worker stores a full copy.

Concrete example: All-reduce sums gradients across replicas; optimizer-state sharding stores different parameter moments on different workers.

Prefill / decode / KV cache

Technical definition: In autoregressive transformer serving, prefill processes prompt tokens to initialize attention state. Decode produces subsequent tokens iteratively. A key-value cache retains prior attention keys and values to avoid recomputing them; its storage grows with cached sequence length and model layout.

In plain language: Read the prompt, generate step by step, and reuse prior attention computations.

Analogy and its limit: Preparing reference notes before writing and consulting them as you continue. Limit: the cache is numerical model state, not an independently searchable fact store.

Concrete example: After processing a 1000-token prompt, append new attention keys and values as each output token is generated.

Quantization

Technical definition: Mapping values to a constrained discrete set or reduced-precision representation, typically using scales and possibly zero points. Model quantization affects numerical error, storage and compute; acceleration depends on supported kernels and hardware.

In plain language: Use fewer representable levels to reduce cost, accepting approximation.

Analogy and its limit: Rounding measurements to a coarser ruler. Limit: smaller files do not automatically imply faster execution or unchanged quality.

Concrete example: Represent a weight block with 8-bit integers plus a scale instead of storing each weight as float32.

Speculative decoding

Technical definition: A decoding method in which a cheap draft proposes tokens and a target model verifies them. With an appropriate acceptance-and-correction procedure, the final sampling distribution matches the target; speed depends on acceptance and overhead.

In plain language: Use cheap guesses to reduce expensive sequential steps while preserving the specified target distribution.

Analogy and its limit: A junior drafts and a senior checks in batches. Limit: ordinary approval heuristics do not guarantee distribution preservation.

Concrete example: Propose four tokens, verify them in one target-model pass and accept a valid prefix under the correction rule.

SLI / SLO / error budget

Technical definition: A service-level indicator is a defined measure of service behavior. A service-level objective sets a target over a specified window and population. An error budget is the allowed unreliability implied by that target and accounting convention.

In plain language: Measure a service property, set its target and track how many misses are allowed.

Analogy and its limit: A speedometer, a speed requirement and an allowance for misses. Limit: an SLO is not necessarily a contractual SLA.

Concrete example: For 100000 eligible requests and a 99.9% success objective, the request-based error budget is 100 failures.

Shadow / canary / rollback

Technical definition: Shadow evaluation runs candidate behavior without controlling the primary response, ideally suppressing external effects. A canary gives a limited population candidate behavior. A rollback restores a prior compatible version or configuration; data and state compatibility must be considered.

In plain language: Observe without control, expose a small group, or restore prior behavior.

Analogy and its limit: A rehearsal, a limited premiere and returning to a previous production. Limit: a rollback cannot automatically undo irreversible actions or schema changes.

Concrete example: Score copied requests with a new model before serving it to 1% of traffic, with a tested compatible rollback.

Injection / poisoning / exfiltration

Technical definition: Prompt injection places adversarial instructions in content crossing a trust boundary to redirect model-mediated behavior. Data poisoning corrupts training or other learned-data processes. Exfiltration is unauthorized transfer of information; it can be an attack consequence rather than the initial vector.

In plain language: Hijack instructions, corrupt learning inputs, or steal data: separate mechanisms require separate controls.

Analogy and its limit: A forged instruction in a document, tampered ingredients and a leaking vault. Limit: suspicious text is not harmful unless the system gives it effective authority.

Concrete example: A retrieved page asks an assistant to send private notes elsewhere; treating that page as an instruction creates an injection path.

Differential privacy

Technical definition: A randomized mechanism is (epsilon,delta)-differentially private if, for neighboring datasets and every output event, its probability on one dataset is at most exp(epsilon) times the probability on the other plus delta. The adjacency relation specifies whose contribution is protected.

In plain language: Changing one protected contribution has a bounded effect on the output distribution; it is not a promise that no fact can be inferred.

Analogy and its limit: A statistical view that limits one contributor's influence. Limit: the guarantee depends on parameters, adjacency, composition and implementation, not just added noise.

Concrete example: Release a bounded-sensitivity count using calibrated noise and account for privacy loss across repeated releases.

First explanation: 16 · Sources: Differential privacy foundations

Equalized odds / calibration

Technical definition: Equalized odds requires the prediction decision to be independent of a protected group conditional on the true label, yielding equal true- and false-positive rates across groups for binary decisions. Calibration requires predicted probabilities to match event frequencies; the two conditions can conflict when base rates differ.

In plain language: Equalized odds compares group error rates; calibration checks probability meaning. One fairness property does not establish all others.

Analogy and its limit: Different gauges: treatment-error balance versus honest probability dials. Limit: social fairness cannot be settled by selecting one metric alone.

Concrete example: A classifier can have equal group true-positive rates yet different false-positive rates, so equal opportunity alone does not establish equalized odds.

Power / p-value / effect size

Technical definition: Power is the probability of rejecting a null under a specified alternative and test design. A p-value is the null-model probability of a statistic at least as extreme as observed under the test's convention. Effect size quantifies the magnitude of a difference or relationship.

In plain language: Detection chance, evidence relative to a null, and practical magnitude answer different questions.

Analogy and its limit: A detector's sensitivity, surprise under no signal, and signal strength. Limit: a small p-value is not the probability the null is true.

Concrete example: A tiny latency reduction may be statistically detectable with many requests while still being operationally unimportant.

Horizon / rolling origin

Technical definition: Forecast horizon is the lead time between a prediction origin and the outcome being predicted. Rolling-origin evaluation repeatedly advances the origin and fits or updates using only permitted historical data, then scores specified future horizons.

In plain language: How far ahead you predict is separate from how you simulate repeated historical predictions.

Analogy and its limit: Move a lookout point along a timeline and look the same distance ahead. Limit: availability delays and retraining cadence still need explicit modeling.

Concrete example: At each month-end, fit on available history and evaluate predictions for the next three months separately by lead time.

Implicit feedback / bandit

Technical definition: Implicit feedback infers preference or utility from behavior such as clicks, confounded by exposure and context. A contextual bandit chooses actions from observed context and learns from rewards for selected actions without observing all alternatives; unlike full RL, it does not model long-term state effects in the basic formulation.

In plain language: Behavior is a noisy preference signal; bandit learning chooses what to expose while learning from partial feedback.

Analogy and its limit: A shopkeeper learns from displayed items' sales. Limit: unsold hidden items provide no direct evidence of dislike, and actions may have unmodeled delayed effects.

Concrete example: A recommender observes clicks only on shown items; randomized exposure with logged propensities supports appropriate offline evaluation.

Representation

Technical definition: An encoding of an object or observation into a form used by a computational process. It can be hand-designed or learned, sparse or dense, symbolic or numerical. An embedding is a vector-space representation with a chosen mapping or geometry.

In plain language: Representation is the general way information is expressed; an embedding is one particular kind.

Analogy and its limit: Different maps of the same city emphasize different information. Limit: every encoding preserves some distinctions and discards or obscures others.

Concrete example: A document can be represented by word counts or by a learned dense embedding; both are representations.

Attention

Technical definition: A mechanism computing input-dependent weighted combinations of value representations using compatibility between queries and keys. Transformer attention typically uses scaled dot-product scores and softmax. External retrieval instead searches a collection to select candidate records or passages; it may supply inputs to attention.

In plain language: Attention mixes accessible representations inside a model computation; retrieval obtains candidates from a collection.

Analogy and its limit: Adjusting a spotlight over material on the desk versus fetching a book from a library. Limit: attention weights are not reliable explanations of causal importance.

Concrete example: A transformer attends over supplied prompt tokens; a retriever first selects manual passages to put into that prompt.

Symbols and units

In attention, T is sequence length and d_k key/query head width; tau is sampling/contrastive temperature. Context specifies any different convention. GB means 10^9 bytes; GiB means 2^30 bytes. A probability has no physical unit; latency, throughput and money do.
